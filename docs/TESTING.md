# 動作検証

アプリを開くだけなら、以下の開発用ソフトは必要ありません。クラウドの作業場所にはすでに検証に使うソフトがあります。

## 毎回使う自動検証

作業場所をこのフォルダにして実行します。Node.js 22以上を使い、追加パッケージのインストールは不要です。

```sh
node --test tests/core.test.js
```

8件の検証で、データの整合性、全ポケモン・技・別名の検索、文字の揺れ、タイプ倍率、ダメージ割合・無効・対象外・確定でHP以上、4つの特殊処理を確認します。さらに18×18の相性と全技×3組（現在1,398通り）の計算を、同じデータを渡した元のv7処理と比較します。この比較は「分割前と同じ動き」の確認であり、「ゲームの全仕様を再現している」ことの証明ではありません。

GitHub側にも `.github/workflows/test.yml` を用意しました。今後変更をGitHubへ送信したときは、この8件を自動で実行します。今回GitHubへの送信はしていないため、GitHub側での実行は未確認です。

## 今回の分割専用の比較

```sh
node --test tests/core.test.js tests/v7-parity.test.js
```

追加4件で原本の保存確認、全データの一致、検索の順序・件数、全ポケモンのタイプ相性を比較します。最新データに更新した後は、v7とのデータ一致は意図的に成り立たなくなるので、普段は `core.test.js` を使います。原本を新データで上書きしないでください。

## ブラウザー操作と見た目の比較

```sh
python3 tests/browser_smoke.py
```

PythonのPlaywright、Pillow、Chromiumを使います。検証用の一時サーバーを自動起動し、終了時に停止します。元のv7と整理後をパソコン幅（1280）・スマートフォン幅（390）で操作し、5機能、入力候補、Enter、エラー表示を確認します。各幅で7画面の表示内容と画像を比較します。表示内容は完全一致、画像は丸い角などの描画時の丸め差（色の値で最大1/255）だけを許容します。

起動中の開発サーバーも確認する場合：

```sh
python3 tests/browser_smoke.py --url http://127.0.0.1:8000
```

直接ファイルを開く検証は、許可されているローカル環境で `--file` を追加します。クラウドでは管理ポリシーで禁止されているため、この方式は未検証です。必要なら `--browser` でChromiumの実行ファイルを指定できます。

今後データや画面を意図的に更新すると原本との比較が変わるため、このブラウザー比較は今回の整理の確認用です。通常の変更では期待値を新仕様に合わせた検証と手動操作を行います。
