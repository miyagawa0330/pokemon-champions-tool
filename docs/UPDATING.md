# 今後の更新の進め方

まず、こちらに変更したい内容を伝えてください。ファイルの編集、動作確認、履歴の保存までこちらで進められます。自分でデータを編集したい場合は、以下を目安にしてください。

1. フォルダを複製するか、Gitで変更前を保存します。`originals` の原本は編集しません。
2. ポケモンは `data/pokemon.js`、技は `data/moves.js` を編集します。
3. `data/settings.js` の確認日・出典を更新します。レギュレーションを変えるときは対象データも合わせて確認します。
4. 自動検証を実行し、ブラウザーでも該当する機能を操作します。
5. `CHANGELOG.md` に変更日・内容・確認結果を書き、Gitで保存します。

## データの注意点

データは `"項目名": 値` の形です。文字は引用符で囲み、数値は囲みません。項目同士はカンマで区切ります。ファイルの最初と最後にあるデータ読み込み用の行は残してください。テキストエディタで保存し、拡張子 `.js` を変えないでください。

- 名前は重複させません。別の姿は別名として登録します。
- `hp`, `attack`, `defense`, `sp_attack`, `sp_defense`, `speed` は種族値です。
- 特性は個別項目に加え、画面用の `abilities_all` と `abilities_description_all` も使います。変更するときは両方を揃えます。
- 技の `category` は `physical`（物理）、`special`（特殊）、`status`（変化）です。
- 技の `power` は数値か `null`（威力なし）です。
- 技の `effect` が空欄だと「効果説明は未登録」と表示します。
- 技の別名検索は `moveAliases` を使います。技ごとの `aliases` はv7から保管した情報です。別名を追加するときは `moveAliases` にも登録してください。
- `special_rule` は計算用の指定です。説明文を書くだけでは計算が変わりません。
- タイプ表は「防御側タイプ → 攻撃側タイプ → 倍率」です。省略された組み合わせは1倍として計算します。
- `settings.nature` はv7では計算に使われません。値を変えても性格補正は付きません。

現在の表示・計算方法を変えるときは、それに対応する検証の期待結果と説明書も更新します。最新データの確認・特性選択・複雑な技の計算対応は、今回の構成整理とは別の変更として履歴に残します。

## Gitを使う場合（こちらで実行できます）

この作業場所にはGitの名前とメールの設定があり、追加操作なしで保存できました。今後の基本操作は、確認 → 編集 → 検証 → 保存です。

```sh
git status
node --test tests/core.test.js
git diff
# 意図したファイルだけを指定して保存する例
git add data/pokemon.js data/settings.js CHANGELOG.md
git commit -m "データ更新: 更新内容を書く"
```

元のv7の保存地点は `pokemon-v7-original`、整理済みの保存地点は `pokemon-v7-foundation` です。復元するときは `git reset --hard` などで現在の作業を消さず、戻したい版と手元の変更を確認してから行います。初心者の方は「前の状態に戻して」と依頼するだけで構いません。

## ZIPに含まれるGit履歴

`history.bundle` は今回の変更までの保存履歴をまとめた復元用ファイルです。通常は開く必要はありません。こちらに「この履歴から復元して」と依頼してください。Gitを使える環境では `git clone history.bundle pokemon-champions-tool` で履歴付きの作業場所を作れます。クラウドの起動手順も現在の5機能版に更新してドラフト保存していますが、新しいクラウドタスクへの復元を確認したという意味ではありません。
